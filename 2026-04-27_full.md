## Executive Summary

Three architectural shifts emerged from independent sub-agents: **(1) Anthropic Citations API replaces the hand-rolled provenance pattern** — cross-validated by the extraction and reasoning research, eliminates a class of hallucinated cites at minimal code cost; **(2) Microsoft Foundry Claude is GA with Sweden Central residency** but does NOT carry a BAA — Anthropic BAA must be contracted separately and Atelier must verify whether it covers Foundry-routed traffic; **(3) the multi-agent Decompose → Search → Verify → Synthesize pattern is now production-validated** by Harvey, CoCounsel, L-MARS / SOLAR / LegalWiz papers — current `reason/checker.ts` separation is correct.

The single highest-cost regression in the codebase: Anthropic silently dropped the default cache TTL from 1h to 5m in March 2026, and the detect prompt (~700-900 tokens) is below Haiku's 4096-token cache floor — a one-hour fix unblocks ~85% input-cost savings on warm calls.

The single highest-risk gate before real-client testing: the engagement-letter AI clause + Anthropic DPA + (if PHI involved) BAA. These are 2-hour-with-outside-counsel artifacts, not engineering.

USCIS PA-2025-16 (Aug 19, 2025) restricts discretionary analysis to NIW only on the EB side — irrelevant to current EB-1A/B/C code path, but flagged for any future NIW expansion.

## Do These Next (Prioritized)

### 1. Fix prompt-caching regressions — **TTL=1h + detect threshold**
**Effort:** 1 hour. **Sources:** Anthropic prompt-caching docs (retrieved 2026-04-27); GitHub claude-code#46829; The Register 2026-04-13.

The detect SYSTEM_PROMPT in `ingest/detect.ts` is below Haiku 4.5's 4,096-token cache floor — `cache_control` is silently no-op. Either move detect to Sonnet 4.6 (2,048-token floor, easier to clear) OR pad the prompt with the canonical authority-cascade list to push it over 4,096. Separately, **all four `cache_control: { type: 'ephemeral' }` instances should pass `ttl: '1h'`** explicitly — Anthropic dropped the default to 5m in early March 2026, biting users mid-pipeline. 1h pays back after 2 reads vs 1 for 5m, almost always worth it for a per-case pipeline. Add `lib/usage-log.ts` to assert `cache_read_input_tokens > 0` after warmup so future regressions are loud, not silent.

**Code pointers:** `ingest/detect.ts:57`, `ingest/claude.ts` (FORMATS lookup site), `draft/cover-letter.ts` (SYSTEM_PROMPTS site), `reason/checker.ts` (SYSTEM_PROMPTS site).

### 2. Adopt Anthropic Citations API — **replaces hand-rolled `{source_page, source_quote}` provenance**
**Effort:** 2-3 days. **Sources:** Anthropic Citations docs; CoCounsel hits 1M users (LawSites Feb 2026); Endex case study showing 10% → 0% hallucinated cites.

The Citations API returns sentence-level pointers (`page_location` blocks) into source documents. Endex measured 10% → 0% hallucinated quotes; CoCounsel/Thomson Reuters uses the same mechanism in production. **Critical: incompatible with `output_config.format` (Structured Outputs).** So extraction continues using prompt-defined JSON shape (no behavior change there) but with documents passed as `document` blocks with `citations: { enabled: true }` and `cache_control` on each. Schema stays the same — `source_page`/`source_quote` populated from returned citation blocks rather than the model fabricating them.

**Code pointers:** `ingest/claude.ts` — restructure user message to pass PDF text as a `document` block; `ingest/schema.ts` — keep schema; the citations get mapped into the `Field<T>` provenance fields server-side. Draft + review can keep current shape; extraction is where the win is.

### 3. Vision fallback for scanned PDFs — **`pdf-parse v2.getScreenshot()` → Claude Vision**
**Effort:** 1-2 days. **Sources:** pdf-parse v2 typedoc; Claude PDF support docs; project memory `feedback_pdf_parse_v2.md`.

`pdf-parse v2` ships native PDF→PNG via `parser.getScreenshot({ scale, partial, desiredWidth })` — no `pdf-to-png-converter` / imagemagick dependency. Replace the current `scan_not_supported` 422 in `ingest/index.ts` with a vision path: render at `scale: 2.0` or `desiredWidth: 2048`, post the PNG via `imageBuffer` into a Sonnet 4.6 vision call (or Opus 4.7 for harder cases). For multi-column legal forms (I-129, DS-160) and non-Latin passports/birth certificates, Claude Vision is the right default; reserve Mistral OCR 3 / Reducto for high-volume batch later if telemetry justifies. **Don't add Marker/MinerU/Unstructured** — Python sidecars are real ops cost; marginal accuracy is recoverable via vision.

**Code pointers:** `ingest/pdf.ts` — extend `extractPdfText` to expose `renderPage(pageNum, scale)`; `ingest/index.ts` — replace 422 branch with vision call.

### 4. Compliance triple — **engagement-letter AI clause + Anthropic DPA + Langfuse audit log foundation**
**Effort:** 2 hours (engagement letter, with outside counsel) + 1 day (DPA signing) + 2-3 days (Langfuse self-hosted bring-up). **Sources:** ABA Formal Opinion 512; CA Practical Guidance; FL Op. 24-1; TX Op. 705; NYC Bar Op. 2024-5; Langfuse self-hosted docs.

These three are mutually reinforcing and operationally essential before the user's stated test plan ("2 real client files" — see project memory): **(a)** engagement-letter AI clause converts the four converged state-bar disclosure obligations into informed client consent and is the single highest-leverage compliance artifact (CA/FL/TX/NY all require it in practice); **(b)** Anthropic DPA signing is same-day and enables EU clients via SCC fallback; **(c)** Langfuse self-hosted v3 is the audit-log substrate that makes every other compliance gate provable in a malpractice or bar-complaint setting — without an immutable log, every other control is unprovable. **Note:** Anthropic BAA is HIPAA-only and Enterprise-tier-only; needed only if Atelier ingests I-693 medical evidence. Foundry Claude does NOT carry a BAA on its own.

**Code pointers:** `lib/audit.ts` (new — Langfuse client wrapper called from every Anthropic call); `docker-compose.yml` — add `langfuse-server` + `clickhouse` + `minio`; `~/atelier-context/legal/` (process artifacts, not code).

### 5. Detect+extract collapse + drop review effort from `xhigh` to `high`
**Effort:** 1 day. **Sources:** Anthropic Effort docs; Anthropic Structured Outputs docs; PADISO routing decision tree (Apr 2026).

The current pipeline runs detect (Haiku) and extract (Sonnet) as two sequential calls. A single Sonnet 4.6 call with a discriminated-union schema returns both `case_type` and the typed extraction in one round-trip. Sonnet at `effort: low` is documented for high-volume classification+extraction work. Eliminates one network round-trip per file (~2-5s latency, one cache write); net cost is roughly a wash (Sonnet ~3× Haiku input cost but replaces TWO calls). Separately, Anthropic explicitly says `xhigh` is for agentic/coding/long-horizon work — not single-pass legal review of an already-Opus-`high`-drafted document. Drop `reason/checker.ts` to `effort: 'high'` (or `'medium'` for E-2 routine renewals) and benchmark before going back up. **Note:** if a 200-doc internal eval shows EB-1A Kazarian-prong gaps caught only at `xhigh`, raise it case-type-conditionally.

**Code pointers:** new `ingest/triage.ts` (replaces `detect.ts` + first call of `claude.ts`, keeps Haiku detect as a fallback for very-large folders); `reason/checker.ts` — `effort: 'high'`.

## Cross-Cutting Findings

These surfaced in multiple sub-agents and warrant standalone treatment.

### CC1. Provenance-as-product — citations are retrieved, never generated
Validated by extraction (F2 Citations API) + reasoning (F3 Citations API) + competitive (F2 CoCounsel pulls from Westlaw, never lets the LLM write the citation string). The architectural rule: **structured authority store + retrieval + sentence-level pointers**, never freeform "see Matter of X" from the model. Atelier's analog: USCIS Policy Manual / 8 CFR / AAO precedents must come from a structured store with the LLM citing IDs. CourtListener (free, BIA + federal cases) + eCFR (free, Title 8) + USCIS Policy Manual (scrape, no public API yet) form the substrate.

### CC2. Multi-agent Decompose → Search → Verify → Synthesize is the validated production pattern
Harvey runs specialty agents (Immigration named publicly) inside per-matter "world models"; CoCounsel separates retrieval-from-Westlaw from generation; L-MARS hit 96.0% vs 58.0% zero-shot on LegalSearchQA; SOLAR 76.4% vs 18.8% zero-shot on SARA; LegalWiz validates the pattern for semi-structured public documents (closest analog to USCIS petitions). **Implication:** Atelier's `reason/checker.ts` separation from `draft/cover-letter.ts` is correct — verification agent ≠ drafting agent. The 6 sub-agents in the ROADMAP (Treaty-Country, Substantial-Investment, etc.) should be wired as orchestrator-worker via tool-use loop, not Managed Agents (still beta, premature lock-in for malpractice-grade workflows). Revisit Managed Agents Q3-2026.

### CC3. Microsoft Foundry Claude — what it buys and what it doesn't
Foundry Claude is GA-grade in April 2026 with Opus 4.7/4.6/4.5/4.1, Sonnet 4.6/4.5, Haiku 4.5 deployable in **East US 2** and **Sweden Central** under the Microsoft DPA. Code change is small (`AnthropicFoundry` SDK wrapper, base URL, optional Entra ID auth). What Foundry buys: Microsoft DPA infrastructure layer, Entra ID keyless auth, EU-resident endpoint via Sweden Central, single Azure invoice, alignment with the user's "Azure deployment target" stack. **What it does NOT buy:** the Anthropic BAA. Anthropic BAA is HIPAA-only, gated to Enterprise+ ZDR contract, post-Dec-2-2025 BAAs may need re-papering. **[NEEDS VERIFICATION]:** whether Foundry-routed traffic falls inside Anthropic BAA scope when both are contracted. Confirm with Anthropic Sales before scoping any PHI ingest. Foundry Sweden Central also explicitly disclaims regional confinement ("prompts and outputs may be processed outside of your region for operational purposes") — does NOT solve GDPR data-residency on its own; SCC + TIA still required.

### CC4. Provenance-aware fact fusion is missing — graph-style entity reconciliation, not naive merge
Validated by extraction (F4) + competitive (F5 Hebbia "don't chunk the petition") + storage (F4 SAC). When a folder has passport + I-94 + employer letter, current code produces N independent fact sets; the drafter has to re-merge and silently picks one when conflicts surface. Pattern: per-file extraction emits typed facts with provenance (already done) → fusion pass groups facts by canonical key (passport number > A-number > full-name+DOB for identity) → rule-based string/numeric similarity catches ~90% → ambiguous clusters routed to Haiku 4.5 reconciliation prompt → conflict surface preserved as a `disputes` array, never silently overwritten. Required for any real case folder.

### CC5. Authoritative source licensing is the immigration-AI moat
The 4-5 named immigration-AI players (Visalaw.AI, QuickFiling, Exelita, Imagility, Docketwise) converge on the same feature set with no public technical architecture. **Visalaw.AI's AILA/AILALink grounding is the only public authority-allowlist analog for immigration.** [NEEDS VERIFICATION]: whether Atelier has access to AILA/AILALink licensing, and whether their AILA grounding is structured retrieval (good) or RAG over scraped HTML (worse). The competitive thesis: Atelier's edge is firm-specific tuning + verifiable provenance, not feature parity.
